# Reviewed draw schedule and prospective evidence

The reviewed calendar remains empty until an actual official page explicitly
establishes the round/date. General weekday information is not sufficient.
A human-reviewed entry requires round, draw_date, source_url, human_reviewed
and reviewed_at_jst. The entry hash is frozen in the shadow ledger; do not
edit or delete an entry after a forecast binds it. A hash is not a publisher
signature or proof that the human review was truthful.

Both the workflow and direct freeze command must use the same validator.
The cutoff is 18:00 JST on the actual draw day, never a ledger-supplied later
time. Training observations must have been verified before issuance and the
training prefix/count must match at assessment. Witness creation and
assessment recheck the schedule entry and cutoff. The repository had no
existing shadow forecasts when this stricter schema was introduced.
The independent GitHub server witness and 500-draw gate are unchanged.

No real calendar dates were approved by this code change. No source access,
forecast skill, or profitability was established.
